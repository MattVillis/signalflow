Signalflow

project file format · version 4
Open the appWhat's newAbout

A SignalFlow project is one JSON file, <name>.signalflow.json. This page describes it for anyone who writes drawings from a script: an equipment database, a patch list, a spreadsheet. It covers every key the app reads, what the app fills in for you, and what will stay compatible. It describes SignalFlow 2.0.12 and later. A JSON Schema sits next to it, and builtins.json lists every built-in symbol with its port ids.

1. What stays compatible

  • The major version is the file format. SignalFlow 2.x writes "version": 4. A change that would make a 2.x file mean something different, or would stop an older 2.x build reading a newer file, waits for SignalFlow 3.0 and "version": 5.
  • Within 2.x the format only grows. New releases add optional keys. A key on this page is not renamed, removed or given a new meaning before 3.0.
  • An older 2.x build keeps what it does not know. Unknown keys on meta, sheets, devices and cables pass through its load and its save untouched.
  • Write "version": 4, but do not rely on it. The app reads a file by the keys it finds and refuses no file for its version number. A version 3 file from SignalFlow 1.x opens too.
  • Leave out what you do not need. Almost everything is optional, and section 17 lists what the app fills in. A file that sticks to the keys on this page, with the types given here, opens in every 2.x build from 2.0.12 on.

2. A first file

A laptop sending HDMI to a projector, both on a switch, on one sheet. Every symbol here is built in, so the library is empty: the app supplies its own built-ins by their ids. Cable numbers, routes and the sheet's page frame are left for the app to fill in.

{
  "version": 4,
  "meta": { "project": "CONFERENCE ROOM", "drawnBy": "SCRIPT" },
  "library": [],
  "sheets": [{
    "id": "s1", "name": "ROOM",
    "devices": [
      { "id": "d-laptop", "defId": "pc-generic-laptop", "label": "PRESENTER", "x": 80, "y": 80 },
      { "id": "d-pj",     "defId": "epson",             "label": "PJ 1",      "x": 480, "y": 80, "ip": "10.0.10.21" },
      { "id": "d-sw",     "defId": "switch8",           "label": "ROOM SWITCH", "x": 480, "y": 264 }
    ],
    "links": [
      { "id": "l1", "a": { "dev": "d-laptop", "port": "p1" }, "b": { "dev": "d-pj", "port": "p0" }, "signal": "video" },
      { "id": "l2", "a": { "dev": "d-laptop", "port": "p3" }, "b": { "dev": "d-sw", "port": "p0" }, "signal": "network" },
      { "id": "l3", "a": { "dev": "d-pj",     "port": "p1" }, "b": { "dev": "d-sw", "port": "p1" }, "signal": "network" }
    ]
  }]
}

p1 on the laptop is its HDMI OUT and p0 on the projector its HDMI IN. Those ids come from builtins.json. Open the file with File > Open in the app, or put it on a web server and open https://mattvillis.github.io/signalflow/?open=<its url>. The server must allow cross-origin requests.

3. The top level

KeyTypeWhen it is missing
versionnumberNot read. Write 4.
metaobjectThe drawing keeps the title block it had before the file was opened. Write it. See meta.
libraryarray of symbolsThe built-ins only. Write your own symbols here; [] is fine.
sheetsarray of sheetsOne empty sheet called SHEET 1.
activenumberThe first sheet. This is the index of the sheet that opens.
view{x, y, k}The view does not move. Screen = canvas × k + (x, y); k is the zoom, from 0.25 to 3.
vlansarrayThis machine's saved VLAN scheme, if there is one. See VLANs.
stylesobjectThe standard drawing conventions. See Drawing conventions.
focusarray of signal kindsNo ghosting. With kinds listed, the drawing opens showing only those, the rest faded.
racksarrayNo racks. See Racks.
imageDataobjectNo pictures. See Pictures.

Unknown top-level keys are ignored. Write the file as UTF-8. Coordinates are canvas units: at 100% a canvas unit is one screen pixel, and on a page frame 3 units are 1 mm of paper. y grows downwards.

4. Ids

An id is any string. The app's own ids look like d1xk2f3a: a prefix, then base-36 time and a counter. Nothing reads that pattern, and the app does not re-key a file's ids.

  • Devices and cables: unique across the whole project, not just their sheet. A cable between sheets names a device on another sheet, and the lists number cables project-wide.
  • Sheets, racks and symbols: unique among their own kind. A rack accessory's id should be unique across every rack.
  • Notes and pictures: unique on their sheet.
  • Ports: unique on their device. A cable names a port by its id.
  • VLANs: num unique.

The app does not repair duplicate ids. Two devices with one id make it pick one of them for every cable.

The paper: meta.page

  • size: "A4", "A3" or "A2". A1 and A0 are written as {"size": "A2", "paper": "A1"} and {"size": "A2", "paper": "A0"}, so a build from before 2.0.8 can still open the file; it prints them scaled onto A2.
  • orient: "portrait", or absent for landscape.

Each sheet then has its own frame on that paper. See Sheets.

6. library: symbols

A symbol is a kind of device: its name, size and ports. A device on a sheet names its symbol by defId.

  • Built-in symbols: leave them out. The app supplies its current built-ins by id. A copy in the file replaces the built-in for that project, which freezes it as it was.
  • Your own symbols: must be in the file. A device whose defId is neither built in nor in the file's library is dropped when the file opens, with a note saying how many.
KeyTypeMeaning
idstringRequired. Unique in the library. Avoid the built-ins' ids unless you mean to replace one.
namestring, ≤36Required. Drawn in capitals in the symbol header. A make and model, e.g. "BARCO E2 GEN 2".
portsarray of portsRequired (it may be empty). See Ports.
widthnumberThe symbol's width in canvas units. The editors keep it between 130 and 280. Default 160.
categorystringThe library sidebar's folder. Default Custom. The built-in categories are Servers, Computers, Processing, LED, Extenders, KVM, Display, Cameras, Network, Audio, Control, Lighting, Power and Custom; any other name makes a new one. Network also turns off auto-IP for the device and offers the switch's CLI port pattern.
classstringThe department in the sidebar's class filter: video, audio, lighting, network, control or power. Without it the class comes from the category, then from the ports.
revintegerBumped by the app on every change to the symbol.
slots, cardsarraysA modular chassis. See below.
physobjectPhysical size and power, for the Racks tab. See below.

Modular symbols: slots and cards

  • slots: [{id, label, accepts, card}].
    • accepts is "in", "out", "link", "aux" or "any", or an array of those.
    • card is the card fitted by default, by card id, or null for an empty slot.
  • cards: [{id, name, kind, ports}].
    • kind is one of the accepts values.
    • ports is a list like a symbol's.
  • How the ports come out: the fitted cards' ports come first, each with the id <slot id>.<card port id>, then the chassis's own ports.

Physical data: phys

  • mount: "rack", "shelf", "none" or "vertical" (2.2.0: a vertical strip, 0U, that stands on an upright beside the rails; mm.h is its length and mm.w its width).
  • Rack units: ru is 1–60, and width is "full", "half", "third" or "quarter".
  • Size and power: mm is {w, h, d} in millimetres; kg is a number; watts and btu are whole numbers.
  • PoE budget: poe is a whole number of watts, what a switch can feed over PoE (2.2.0). It may sit in a block with no mount.
  • Where each connector is on the panels: at is {<port id>: ["f"|"r", x, y]}, with x and y in percent of that face as seen looking at it. A card's bay goes in bays: {<slot id>: ["f"|"r", x, y, width]}. Since 2.2.0 a card's connector may have a place of its own in at, under the id the app gives a card's port, <slot id>.<port id>; the card's other connectors keep to its bay.

7. Ports

KeyTypeMeaning
idstringUnique on the symbol. On a library symbol it may be left out: the app numbers ports p0, p1 … in list order. On a device's override give every port its id; since 2.0.12 one without is numbered the same way.
labelstring, ≤24Required. Drawn as written; the app's editors write capitals.
side"left", "right"Required. Which side of the symbol. Each side lists its ports top to bottom in array order. Before 2.0.12 any other value stopped the drawing; it now reads as left.
dir"in", "out", "bi"Signal direction; default bi. Sets the arrowheads and what may be cabled to what.

modulestring ≤24(2.3.0) The SFP module in a cage port (connector SFP, SFP+, SFP28, QSFP+ or QSFP28), as typed: an optic such as "10GBASE-LR" or "10G BIDI 1270", or "DAC". Each end of a cable has its own.

8. Built-in symbols and their port ids

builtins.json lists every built-in symbol of the current release:

{ "version": "2.0.12",
  "symbols": [ {
    "id": "epson", "name": "EPSON PROJECTOR", "category": "Display", "width": 160, "ports": 3,
    "ids":  ["p0", "p1", "p2"],
    "list": [["HDMI IN", "left", "in", "video", "HDMI", 0, -1], ["LAN", "left", "bi", "network", "RJ45", 0, -1], …],
    …
  }, … ] }
  • ids and list: the symbol's ports with its default cards fitted, in the order the app expands them. ids[i] is the id of the port list[i] describes. Each list entry is [label, side, dir, signal, conn, gap, group].
  • Modular symbols also have slots, [[id, label, accepts, default card id], …], and cards, [{id, name, kind, ports: [[id, label, side, dir, signal, conn], …]}]. They let a script fit other cards and work out their port ids.

Take port ids from builtins.json rather than counting. Most built-ins number their ports p0, p1 … in order, but card ports are <slot>.<port> and come first, and a few symbols name their own ports (the grandMA3 desks, so that cables on older drawings stay put). A port id on a built-in is not changed in a later release.

9. Sheets

KeyTypeMeaning
idstringRequired. Unique.
namestringRequired. The sheet's tab. The app's own renaming stops at 18 characters; longer names load.
titlestring, ≤48The title block's DRAWING for this sheet (2.0.11). Without it, the sheet's name.
devicesarraySee Devices. Later entries draw on top.
linksarraySee Cables.
notesarrayText notes and zones. See Notes.
imagesarraySee Pictures.
page{x, y, w?}The page frame: its top-left corner in canvas units and its width (none = the paper at 100%, 3 units a millimetre). Leave it out and the app places it round the drawing the first time the sheet is shown with a paper size set.

10. Devices

KeyTypeMeaning
idstringRequired. Unique across the project.
defIdstringRequired. The symbol: a built-in's id, or one in the file's library.
x, ynumberRequired. The symbol's top-left corner. The app's grid is 8; nothing needs to sit on it.
labelstringThis device's name: PJ 1, MAIN SERVER. Without it, the symbol's name is shown.
ipstringThe device's address, shown under its name when the symbol has one network port.
host, mac, assetstringsHostname (≤253), MAC address as "AA:BB:CC:DD:EE:FF", asset number (≤32) (2.0.11). Listed in Lists > DEVICES.
slotsobjectA modular device's cards: {<slot id>: <card id> | null}. A slot not named keeps its default card.
override{width?, ports}This device's own port list, replacing its symbol's. ports is the complete, expanded list. Keep the symbol's port ids for the ports it shares with it.
collapsedtrueDraws only the ports something is plugged into.
ifPatternstringA Network symbol's port names on its own CLI, with {n} counting its network ports, e.g. "1/0/{n}".
rack{id, u, x, rear?, mid?, turn?, group?, post?}Its place in a rack. mid: true (2.3.0) hangs it from the rack's mid rails (a rack without them reads it as the front rails). A vertical strip (2.2.0) stands on an upright: post is "l" or "r" seen from the front, rear: true the rear uprights, u the unit its foot is at, and x is 0. u is the lowest unit it fills, 1 = the bottom. x is millimetres from the left of the 450 mm opening, seen from the front. rear: true hangs it from the rear rails. turn (2.2.0) says which way round it is: true = its front panel faces the back of the rack. Without turn a unit on the rear rails is turned round, which is what rear alone meant before 2.2.0, so write turn: false for one on the rear rails that faces the front. group (2.2.0, a string) ties devices in one rack together: the rack view moves them as one. The rack must be in racks.

Two kinds of device are made by the app and are best left to it:

  • external: the hidden far end of a cable to a place off the drawing.
  • patchpanel: the symbol of a patch panel in a rack. Write the panel as a rack accessory and the app makes its symbol.

11. Cables (links)

KeyTypeMeaning
idstringRequired. Unique across the project.
a, b{dev, port}Required. The two ends, by device and port id. The arrow is drawn at b, so write it as source → destination.
signalsignal kindRequired. What the cable carries, which sets its line style. Usually end a's port signal.
mode"auto", "manual", "flag"Default auto (the app routes it). manual runs through pts. flag draws no line, only a flag at each end naming the other.
pts[{x, y}]The waypoints of a manual route.
offnumberA nudge, in canvas units, of an auto route's middle run.
nowhole number ≥1The cable number (C001). Leave it out: the app numbers new cables and keeps numbers it is given.
cablestring, ≤40The cable type as ordered: CAT6A, 12G SDI, OM3 LC–LC (2.0.9).
lennumberIts length in metres, whatever the project shows (2.0.9).
loomstring, ≤32The loom or multicore it runs in (2.2.0): cables with the same name are listed together.

A cable to another sheet

Store it on the sheet of end a. Give end b the far sheet's id, as in "b": {"dev": "d-pj", "port": "p0", "sheet": "s2"}, and use "mode": "flag". It is drawn as a flag on each sheet. The file keeps it only when b.dev really is on that sheet, and it is not this one.

What the app checks

The editor refuses some cables: a second cable on a port (except a breakout DAC's trunk), an output into an output, and connectors that do not mate without a converter. The loader checks none of this, so a file can hold cables the editor would refuse. A cable is dropped on load only when a device it names is not on its sheet. A cable to a port the device does not have is kept, but not drawn.

12. Text notes and zones

Both live in a sheet's notes:

  • A text note is {id, type: "text", x, y, text, color?, fs?}. text may hold line breaks (\n).
  • A zone, a titled box round part of the drawing, is {id, type: "box", x, y, w, h, text, color?, fs?}, with the title as text.
  • Common keys: color is #RRGGBB, default #1A1A18. fs is the text size, 8–36. text is required; since 2.0.12 a note without it is read as empty.

13. Pictures

  • On a sheet: images is [{id, img, x, y, w, h, name?, op?, lock?, front?}].
    • img names a picture in the project's imageData, so one picture can be placed many times.
    • x, y, w and h are the box in canvas units.
    • op is the opacity, 0.05 to below 1.
    • lock: true stops it being moved. front: true draws it over the cables instead of under them.
  • In the project: imageData is {<img>: {data, w, h}}.
    • The key is im and then 4–40 lower-case letters or digits.
    • data is a PNG or JPEG data: URL, up to 8 million characters.
    • w and h are its pixel size.

14. VLANs

  • The list: vlans is [{num, name, color, subnet?, start?}].
  • num: a string, e.g. "10". Ports name a VLAN by it.
  • name is up to 16 characters, and color is #RRGGBB.
  • subnet: the network's first three numbers, e.g. "192.168.10". The app numbers devices in it from start (1–254, default 10).

Since 2.0.12 a subnet written as "192.168.10.0/24" is read as "192.168.10".

15. Drawing conventions: styles

KeyMeaning
sigLine styles that differ from the standard ones: {<key>: {c, dash, w, label}}. A key is a signal kind, a video connector (12G SDI, 6G SDI, 3G SDI, HD SDI, HDMI, DP, DVI) or a group (SPEAKER, RF, DMX, TIMECODE). c is #RRGGBB. dash is an SVG dash pattern such as "6 3", or "". w is the line width, 0.5–5. label is the legend's name for it.
hopsWhere cables cross: "none", "arc" or "gap".
textCase"typed" keeps names as written; absent = CAPITALS.
cableLabelsfalse turns off the small labels at each end of a cable (2.0.9).
fontThe drawing's fonts: {text?, head?}, each {family, src: "free" | "file"}. free names a font on Fontsource. file names one installed on a machine, which other machines will not have.

16. Racks and accessories

racks is [{id, name, u, depth?, mid?, row?, col?, acc?, notes?}]:

  • The frame: u is its height in units (1–60, default 42) and depth its depth in millimetres (default 800). mid (2.3.0) gives it mid rails, that many millimetres behind the front rails; without it there are none.
  • Notes (2.3.0): notes is [{id, x, y, text, size?, view?}], text written on the Racks tab. x and y are millimetres from the top left of the rack's frame, text may hold line breaks (up to 400 characters), size is the text height in millimetres (9, 14 or 22; 14 when not given) and view is "front", "rear" or "side", the one view it shows in (none: every view).
  • The layout: row and col place it in the Racks tab's grid. Without them, racks stand in one row in list order.
  • Devices: they go in a rack by their own rack key (Devices).

acc lists the rack's accessories:

  • Every accessory: {id, kind, u, h, face, label?}.
    • kind is blank, brush, vent (2.3.0), fan, drawer, shelf (2.3.0) or patch.
    • u is its lowest unit and h its height in units.
    • face is the rails it is on: "f" or "r".
  • A drawer and a shelf take depth (mm), and a fan panel takes fans (1–12). What stands on a shelf is not stored with it: a device on the shelf's rails whose lowest U is one of its rows stands on it, and moves with it.
  • A patch panel takes rows (1–6), cols (1–48) and ports.
    • ports is [{c, l?, m?}] in reading order: c is a connector, l a label, and m: true makes an XLR male. c may be "D HOLE", "D BLANK" or (2.2.0) "EMPTY", a position with nothing in it.
    • w and x (2.2.0): a panel narrower than the rack, w millimetres wide (40–449) and x millimetres from the left of the 450 mm opening, seen from the front. Without w it is full width.
    • The app gives every patch panel a symbol on a sheet, so its connectors can be cabled.

17. What the app does with a file

When it opens one

  • Built-in symbols: supplied by id, and missing port ids on symbols numbered.
  • Devices whose symbol is nowhere: dropped, with a note saying how many.
  • Cables: those whose devices are not where they say are dropped. Missing mode and pts are filled in.
  • Cable numbers: those given are kept. Cables without one get the next free numbers. Of two cables claiming one number, the first keeps it.
  • Racks: their values are kept in range and their grid closed up. A device's rack place is kept only in a rack the file has.
  • Pictures: those with no box or no data are dropped.
  • Since 2.0.12, unworkable values are repaired so the drawing opens:
    • a port side that is not left or right reads as left;
    • a port without a label gets an empty one;
    • a symbol without a width or category gets 160 and Custom;
    • an override without a port list is dropped;
    • a note without text gets an empty one;
    • a sheet, device or cable without an id gets one;
    • active is kept in range;
    • VLAN subnets are read as their three numbers.

Soon after

  • Patch panels: each rack patch panel gets its symbol on a sheet.
  • External far ends: one that no cable uses is removed.
  • Page frames: each sheet's frame is placed when the sheet is first shown with a paper size set.

When it saves

Everything is written in full: every key above, and the whole library, built-ins included. A file the app has saved is a good example of anything this page leaves unclear.
